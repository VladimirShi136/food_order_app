# Roadmap: приложение для заказа еды «Gari Grill» (гриль/фастфуд)

Проект: каталог блюд → онлайн-заказ → самовывоз (в будущем — доставка)
Стек: Flutter (Android, затем iOS) + provider + PocketBase (self-hosted, сервер в РФ)

**Статус на 10.10.2026:** приложение целиком работает с локальным PocketBase (v0.40.4): меню, новости и акции, авторизация, оформление заказа, история и статусы заказов (realtime). Меню и новости доступны из локального кеша при проблемах со связью. Дальше — перенос на сервер, оплата, роль сотрудника/админ-панель.

## Решение по backend — PocketBase на российском сервере

**Почему не Supabase/Firebase:** по 152-ФЗ (ужесточён 23-ФЗ с 1 июля 2025) персональные данные граждан РФ (имя, телефон, адрес) должны храниться на серверах, физически расположенных в РФ. Облачные Supabase/Firebase этому не удовлетворяют. Требование касается географии сервера, а не происхождения ПО.

**Почему PocketBase:** open-source, один исполняемый файл (~15 МБ, Go), внутри SQLite, авторизация, файловое хранилище, realtime и админ-панель в браузере. Официальный Dart/Flutter SDK — пакет `pocketbase` на pub.dev.

**Стратегия: сначала локально, потом сервер.**
- Разработка идёт с локальным PocketBase на компьютере (`./pocketbase serve`, админка: `http://127.0.0.1:8090/_/`).
- Все данные (`pb_data/data.db`, фото в `pb_data/storage`) и схема (`pb_migrations/`) переносятся на сервер без потерь.
- Версия PocketBase на сервере должна совпадать с локальной (или быть новее — обновление применит миграции).

**Как подключаться из приложения в локальной разработке:**
- Android-эмулятор: `http://10.0.2.2:8090`
- Реальный телефон: `http://<IP компьютера в Wi-Fi>:8090` (телефон и ПК в одной сети; PocketBase запускать с `--http=0.0.0.0:8090`)
- Для http (не https) на Android в debug нужен `usesCleartextTraffic="true"` в манифесте — только для разработки, в релизе только https
- Адрес сервера вынести в одну константу/конфиг, чтобы переключение local → prod было одной правкой

**Что не коммитим в git:** бинарник `pocketbase` и `pb_data/` (добавить в `.gitignore`). Коммитим `pb_migrations/`.

**Сервер (когда понадобится):**
- Провайдер: Timeweb Cloud, Selectel или REG.ru (ЦОД в РФ)
- Параметры: 2 ядра, 4 ГБ RAM, 40 ГБ NVMe — с запасом для города на 30 000 жителей
- Ориентир по цене: Timeweb Cloud «Cloud NVMe 4» ≈ 1460 руб/мес
- Домен .ru (~250 руб/год), SSL Let's Encrypt (бесплатно), автобэкапы (опционально, +200–300 руб/мес)
- Итого ≈ 1700–1800 руб/мес на старте

## Заметки по разработке
- **Принцип:** сервер — источник истины. Что приходит с телефона — пожелание клиента: цену, итог, номер, статус и владельца заказа ставит и проверяет сервер (`backend/pb_hooks/orders.pb.js`). Скидки и акции с изменением цены тоже должны считаться на сервере.
- **Схема БД живёт в миграциях** `backend/pb_migrations/` (коммитятся). Изменил коллекцию в админке — закоммить новую миграцию.
- **Серверная логика** — `backend/pb_hooks/` (JS-хуки PocketBase). Подхватывается при запуске PocketBase; на сервере папка должна лежать рядом с бинарником.
- **Адрес сервера** задаётся при запуске: `flutter run --dart-define=PB_URL=http://<IP компьютера>:8090` (по умолчанию `http://10.0.2.2:8090` — эмулятор). Для боевого сервера поменять значение по умолчанию в `lib/config.dart`.
- **Ловушка с `Stack`:** если внутри `Stack` единственный обычный (не `Positioned`) элемент маленький, то `Stack` сжимается до его размера, а `Positioned.fill` заполняет только этот кусочек. Для полноэкранных наложений использовать `Stack(fit: StackFit.expand, ...)` и оборачивать остальное в `Positioned`.
- **Переходы между экранами:** при правках `_NoFlashSlideTransitionsBuilder` (`lib/theme/app_theme.dart`) входящий и уходящий экраны должны использовать одну и ту же кривую.
